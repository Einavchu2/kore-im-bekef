# קוראים בכיף: גרסה 1.2.0

גרסה זו מוסיפה לאפליקציה שירות קול בשרת (Netlify Functions) שמדבר עם Sonex Labs. מפתח ה־API נשמר רק בשרת. האפליקציה, התרגילים, הניקוד, הקבוצות וכל שאר הפונקציונליות לא השתנו.

## תרגול ומעבר בין קבוצות (חדש ב־1.2.0)

- **מאגר:** בכל קבוצה 3,200 תרגילים שונים בתוכן. תרגיל שההבדל היחיד בו הוא סדר התשובות לא נספר כתרגיל חדש.
- **תרגילים נשלטים:** תרגיל שהילד/ה פתר/ה נכון בניסיון הראשון פעמיים לא יוצג לו/ה שוב. כל ילד/ה עם רשימה משלו/ה, ובאזור המורים מוצג כמה תרגילים כל אחד/ת כבר שולט/ת בהם.
- **מעבר קבוצה מוצע רק כשההצלחה קבועה:** לפחות 40 תרגילים בקבוצה, ו־20 התרגילים האחרונים כולם בלי טעות. הילד/ה בוחר/ת "כן, אני עובר/ת" או "עוד קצת כאן". אחרי "עוד קצת כאן" ההצעה חוזרת רק אחרי 10 תרגילים נוספים בלי טעות.
- **בקבוצה הכתומה שני סוגי תרגיל חדשים:** "איזה כרטיס שונה" ו"מצאו את הכרטיס עם הניקוד הזה".

## פרסום בלי שרת הקול

אם עדיין לא הוגדר Sonex, אפשר לגרור ל־Netlify רק את התיקייה `public`. האפליקציה תעבוד עם קול המכשיר, כמו קודם.

## מבנה הפרויקט

| נתיב | תפקיד |

| `public/index.html` | האפליקציה. שירות הקול החדש הוא המודול `Speech` |

| `netlify/functions/tts.mjs` | `GET /api/tts`: הקול שהאפליקציה מבקשת |

| `netlify/lib/pronunciation.mjs` | הפרדה בין הטקסט שמוצג לילד/ה לבין הטקסט שנשלח למנוע |

## איך זה עובד

- **הוראות ומשוב** ("כל הכבוד!", "סדרי את הצלילים"): נוצרים ב־Sonex בפעם הראשונה ונשמרים בשרת. מאז הם מושמעים מהזיכרון בלי לפנות שוב ל־Sonex.
- **שם הילד/ה לא נשלח ל־Sonex.** משפט כמו "היי נועה!" נשלח כ"היי!".
- **פריטי לימוד** (מילים, צלילים, משפטים, שמות ניקוד): **לא נוצרים אוטומטית.** הם מושמעים רק אחרי שמבוגר יצר דוגמה בדף הבדיקה, האזין לה ואישר אותה, או העלה הקלטה משלו. הקלטה מאושרת משמשת בכל המכשירים.
- **פריט לימוד שעדיין לא אושר:** באזור המורים (⚙️) בוחרים מה קורה. אפשר להשמיע בקול המכשיר, שזו ההתנהגות של היום ומסומנת "לא נבדק". אפשר גם לא להשמיע בכלל, ואז תרגילי שמיעה מוחלפים אוטומטית בגרסה חזותית.
- **תקלה או המתנה ארוכה:** אחרי 7 שניות לכל היותר הילד/ה ממשיך/ה. הוראות ומשוב עוברים לקול המכשיר. פריטי לימוד עוברים לקול המכשיר רק אם המבוגר אישר זאת.

## הגדרה: צעד אחר צעד

### 1. מפתח Sonex

1. נרשמים ב־sonexlabs.com.
2. בתפריט: Configurations ← Developer ← API Keys ← Create key.
3. מעתיקים את המפתח מיד, כי הוא מוצג פעם אחת בלבד. מפתחות מתחילים ב־`vsk_`.

### 2. משתני סביבה ב־Netlify

בפרויקט kore-im-bekef: Project configuration ← Environment variables ← Add a variable.

| משתנה | ערך | חובה |
|---|---|---|
| `SONEX_API_KEY` | המפתח מ־Sonex. ה־Scope חייב לכלול **Functions**. אם יש אפשרות לסמן כסוד, מסמנים | כן |
| `TTS_ADMIN_PASSWORD` | סיסמה ארוכה לדף הבדיקה | כן |
| `SONEX_VOICE_ID` | מזהה קול התחלתי. אפשר לבחור קול גם מדף הבדיקה | לא |
| `TTS_DAILY_NEW_LIMIT` | כמה משפטי ממשק **חדשים** מותר ליצור ביום (ברירת מחדל: 300) | לא |

אחרי שינוי משתנים צריך לפרסם מחדש (deploy), כי הערכים נקלטים בזמן הפרסום.

### 3. פרסום

הגרסה הזו כוללת קוד שרת, ולכן **גרירה של תיקייה לא מספיקה**. יש שתי דרכים:

**א. GitHub (מומלץ, עדכונים אוטומטיים):**
1. יוצרים מאגר חדש ב־GitHub ומעלים אליו את כל התיקייה, חוץ מ־`node_modules`.
2. ב־Netlify: Project configuration ← Build & deploy ← Link repository, ובוחרים את המאגר.
3. ההגדרות נקראות מ־`netlify.toml`, אין צורך למלא כלום.
4. כל שינוי שנשמר במאגר מתפרסם אוטומטית.

**ב. Netlify CLI מהמחשב:**
```bash
npm install
npx netlify login
npx netlify link          # בוחרים את kore-im-bekef
npx netlify deploy --prod
```

### 4. הרצה מקומית

```bash
cp .env.example .env      # ממלאים מפתח וסיסמה. הקובץ .env לא נשמר ב־Git
npm install
npx netlify dev           # האפליקציה ב־http://localhost:8888, דף הבדיקה ב־/review.html
npm test                  # בדיקות יחידה (לא צריך מפתח)
```

## אחרי הפרסום: אישור הקלטות

1. נכנסים ל־`/review.html` עם הסיסמה. אפשר להגיע גם מאזור המורים באפליקציה, בקישור "בדיקת הקלטות והגייה".
2. **מצב והגדרות:** בוחרים קול ומכוונים מהירויות.
3. **מבחן הגייה:** מאזינים ל־59 הפריטים ומסמנים "נשמע נכון" או "שגוי". מייצאים CSV.
4. **פריטי לימוד:** לכל פריט (419 בסך הכול):
   1. "צור דוגמה" ומאזינים.
   2. אם ההגייה שגויה, מתקנים את "טקסט למנוע" (למשל ניקוד מלא יותר), שומרים, ויוצרים דוגמה חדשה.
   3. כשנשמע נכון, לוחצים "אשר". אפשר במקום זה להעלות הקלטה של המורה.
5. אפשר ליצור דוגמאות לרשימה מסוננת בבת אחת. האישור הוא תמיד לכל פריט בנפרד, ורק אחרי האזנה.

## מגבלות ועלויות (לפי התיעוד של Sonex, נבדק ב־26 באוקטובר 2026)

- **בהרשמה:** 10,000 תווים חינם, בלי כרטיס אשראי. התיעוד מתאר הענקה חד־פעמית ולא מזכיר מכסה חודשית מתחדשת. לקרדיטים עשוי להיות תאריך תפוגה: בדף הבדיקה מוצגת היתרה, ואת התאריך אפשר לראות בלוח הבקרה של Sonex.
- **אחרי זה:** 0.03125$ לכל 1,000 תווים.
- **הערכה לאפליקציה:**
  - יצירה חד־פעמית של כל 419 פריטי הלימוד: כ־4,000 תווים.
  - משפטי ממשק: כ־1,500 עד 4,000 תווים.
  - סך הכול כ־5,500 עד 8,000 תווים. זה בתוך המכסה החינמית, אבל כל יצירה חוזרת של דוגמה נספרת.
  - אחרי המכסה, 10,000 תווים נוספים עולים כ־0.31$.
  - סימני ניקוד נספרים כנראה כתווים. המספר המדויק מופיע בכל דוגמה ("X תווים").
- **השמעה חוזרת לא עולה כלום:** קול שכבר נוצר נשמר בשרת, ב־CDN ובמכשיר.
- **מגבלות קצב של Sonex:** 5 בקשות בשנייה, 120 בדקה. בשרת יש גם הגבלת קצב לכל כתובת IP ומגבלה יומית על יצירת משפטים חדשים.
- **עלויות Netlify:** הפונקציות והאחסון (Blobs) צורכים ממכסת המסלול של Netlify. בשימוש של כיתה הצריכה צפויה להיות נמוכה, אבל כדאי לבדוק את המכסות במסלול שלכם.

## מגבלות חשובות של Sonex לעברית

- **אין קול עברי מקורי.** הקולות קוראים עברית במבטא של השפה שבה הוקלטו. למבטא ישראלי צריך לשכפל קול של דובר/ת עברית (10 שניות הקלטה), ורק בהסכמה של בעל/ת הקול.
- **ניקוד:** Sonex מתעדים קריאה של עברית **בלי** ניקוד, וממליצים להוסיף ניקוד רק למילה דו־משמעית. התיעוד לא מבטיח שטקסט מנוקד מלא, או צליל בודד כמו "דָ", ייקרא לפי הניקוד. לכן כל פריט לימוד עובר האזנה ואישור.
- **שליטה בקול:** ה־API מאפשר לבחור רק קול ומהירות. אין פרמטרים לרגש או לסגנון. ה"סגנונות" (שבח, עידוד, הוראה) נבדלים רק במהירות ובניסוח.
